Rally Point App Specification
Overview
The Rally Point app is a comprehensive mobile and web application designed to support field operations, community engagement, administration, Bible worker coordination, and a Literature Evangelist Program (Light Squads, Angel Squads, Evangelism Cycles). The app will be built using modern web technologies (React with Tailwind CSS) to ensure cross- platform compatibility and scalability.
Functional Requirements In the Field
1. Geotracking:
o Real-time GPS tracking of field workers.
o Record and display paths taken during fieldwork.
2. DeliveryTracking:
o Option to mark book deliveries as "to door" or "to person." o Log delivery locations with geocoordinates.
3. Surveys:
o Create, distribute, and collect surveys at the door.
o Admin interface to modify or create new surveys dynamically.
4. WalkieTalkie:
o Real-time voice communication between team members within the app.
5. Donations/Payments:
o Secure in-app payment processing for donations (e.g., Stripe integration).
o Support for multiple payment methods (credit card, digital wallets).
o Support offline donations with later syncing, including manual entry for cash donations and digital receipt generation.
o Developer Note: Use IndexedDB for queued transactions, with encryption for stored payment data; sync with Stripe when online.
6. TerritoryManagement:

o Interactive map interface for selecting/assigning work areas.
o Prevent overlapping assignments with real-time territory locking. o Request/assign new territories via team leader/admin approval.
7. DistanceCovered:
o Track and report distance traveled by field workers (calculated via GPS).
8. MapAccess:
o Embedded maps (e.g., Google Maps or OpenStreetMap) for navigation within
the app.
9. OfflineFunctionality:
o Support offline mode for geotracking, delivery tracking, surveys, and payments, with data syncing when internet is restored.
o Developer Note: Use service workers and IndexedDB for local storage to ensure seamless operation in low-connectivity areas.
10. Augmented Reality (AR) Navigation:
o Implement AR to visualize assigned territories or delivery points via phone
camera, starting with marker-based AR (e.g., QR codes).
o Developer Note: Integrate AR.js or a similar lightweight AR library for cross- platform compatibility.
11. Real-Time Weather Integration:
o Display weather conditions for assigned territories to aid fieldwork planning.
o Developer Note: Use a weather API (e.g., OpenWeatherMap) to fetch real- time data based on geolocation.
12. Safety Alerts:
o Include a panic button for field workers to send an SOS with their location to
team leaders or admins.
o Developer Note: Implement push notifications and SMS alerts using Firebase Cloud Messaging or Twilio.
13. Real-Time Collaboration Tools:

o Add a shared digital whiteboard or note-taking feature for field teams to collaborate on territory plans or share real-time observations.
o Developer Note: Use a real-time collaboration library like Yjs with WebRTC for low-latency syncing, integrated into the app’s map interface.
14. Task Checklists:
o Provide customizable checklists for field workers to track daily objectives
(e.g., number of doors to visit, surveys to complete).
o Developer Note: Store checklists in the database with a drag-and-drop UI using React-Beautiful-DnD; allow pre-populated task templates based on territory type.
15. Voice-to-Text Notes:
o Enable field workers to record quick voice notes that are transcribed and
saved for later review or sharing.
o Developer Note: Integrate a speech-to-text API (e.g., Google Cloud Speech- to-Text) for real-time transcription; test accuracy for various accents and noisy environments.
16. Dynamic Territory Feedback Loop:
o Allow field workers to submit real-time feedback on territories (e.g.,
accessibility, receptiveness) to inform future assignments.
o Developer Note: Add a feedback form to the Territory Management interface, with responses stored in Firestore/MongoDB and viewable in the Admin Dashboard’s Master Map; use anonymized feedback for privacy.
17. Field Worker Training Hub:

on door-to-door techniques, survey delivery).
o Developer Note: Host content in the Resource Vault with a “Field Training” tab, using existing video hosting infrastructure; include progress tracking and offline access.
18. Digital Receipts for Donations:
o Auto-generate PDF receipts for online and offline (cash) donations for donor trust and tax compliance.

o Developer Note: Use jsPDF to generate branded receipts, integrated with Donations/Payments; store receipts in Firestore/MongoDB and allow offline generation with sync.
19. Barcode Scanning for Inventory:

tracking.
o Developer Note: Use Firebase ML Kit or a barcode scanning library (e.g., QuaggaJS) with device camera; support ISBNs with manual entry fallback; integrate with Inventory Management.
20. Safe Check-In Timer:

period (e.g., 2–4 hours) for safety.
o Developer Note: Integrate with GPS and Safety Alerts, using Firebase Cloud Messaging/Twilio for alerts to multiple recipients; allow customizable intervals.

multilingual support.
o Developer Note: Integrate Google Translate API or offline libraries (e.g., i18next); cache translations offline and ensure theological accuracy.

areas lighting up based on the number of books distributed.

Development Notes
• Use CDN-hosted React and dependencies (e.g., cdn.jsdelivr.net).
• Avoid <form> onSubmit due to sandbox restrictions; use button event handlers
instead.
• Ensure all components are reusable and modular, with configurable enable/disable options for features.
• Implement a single-page application (SPA) architecture for seamless navigation.
• Test geotracking, AR (navigation, prayer maps, distribution map), and map features
thoroughly for accuracy, ensuring colorblind-friendly heatmap and AR designs.
• Optimize map rendering, heatmaps, timelines, and real-time features to minimize battery drain using adaptive polling.
• Ensure admin dashboard, reporting tools, and analytics are optimized for large datasets with caching.
• Verify scalability for large community events and mission trip sign-ups.
• Test accessibility with tools like Lighthouse to ensure WCAG 2.1 compliance for all
components.
• Implement lazy loading for heavy components (e.g., heatmaps, timelines, archives, AR maps) to reduce load times.
• Audit APIs for security vulnerabilities, especially for sensitive data like contact timelines, referrals, offline payments, and child data.
• Monitor API costs (e.g., Google Maps, Stripe, Twilio) with usage quotas and explore nonprofit discounts.
• Create video tutorials for onboarding, hosted in the Resource Vault, tailored to user roles, including training for barcode scanning and voice commands.
• Plan for phased rollout:
o Phase 1: Core field features (geotracking, delivery tracking, surveys, territory management, offline payments, digital receipts, barcode scanning, safe check-in timer), basic community features (messaging, news feed, mission trip sign-ups, volunteer skill database, child check-in), and essential admin reports (including conflict resolution logs).

o Phase 2: Community enhancements (podcasts, live events, gamification, mentorship, polls, prayer wall, mission trip hub, testimony sharing hub), Bible worker tools (scheduling, timelines), and leader training modules, equipment tracking, customizable permission tiers.
o Phase 3: Advanced features (AR navigation, AR prayer maps, AR Great Controversy distribution map, AI analytics, wearables, multi-tenancy, budget tools, API usage dashboard).
